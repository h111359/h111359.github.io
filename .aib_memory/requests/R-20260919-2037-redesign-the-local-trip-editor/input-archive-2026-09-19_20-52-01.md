## Input

### Goal

Redesign the local trip editor to give the site owner a clear, consistent workflow: select a trip, select a part, then edit its content. Replace the crowded combined interface with focused screens and breadcrumbs while preserving existing authoring functionality.

### Screens and navigation

#### Trip landing screen

- Launching trips/start-editor.sh or trips/start-editor.bat opens the trip landing screen.
- Show existing trips as a compact, title-only list.
- Provide a clearly visible Create new trip action.
- Selecting a trip opens its parts screen.
- After successful trip creation, open its parts screen with an empty state and an Add first part button.

#### Trip parts screen

- Show the selected trip’s title and a compact, title-only list of its parts in their published order.
- Selecting a part opens its content editor.
- Place trip settings and part-management actions on this screen.
- Support part creation, title changes, ordering, and deletion.
- Preserve stable saved part slugs and filenames when changing displayed titles.
- Offer Create blank part and Import from Google Drive.
- Open the part editor after successful creation.
- Preserve the existing review and confirmation flow for Google Drive imports and replacement.
- Keep trip settings and management forms secondary to the parts list, revealing them when needed.

#### Part editing screen

- Show the selected part’s title, its content elements, formatting controls, and a clearly visible Save action.
- Preserve existing item creation, editing, deletion, ordering, rich-text formatting, visibility, media corrections, refresh, preview, and AI controls.
- Make primary editing actions easy to find and group secondary controls clearly.
- Keep trip settings and part management on the parent parts screen.

#### Breadcrumbs and navigation

- Show breadcrumbs reflecting the hierarchy: Trips → Trip title → Part title.
- Ancestor breadcrumbs navigate to their corresponding screens.
- Clearly distinguish the current location.
- Support browser Back and Forward navigation consistently with the screen hierarchy.
- On a fresh launcher opening, show the trip landing screen.

### Unsaved changes

- When navigating away would leave unsaved changes, offer Save and continue, Discard and continue, and Stay.
- Save and continue completes navigation only after the affected changes save successfully.
- A validation or save failure retains edits and keeps the user on the current screen with an actionable message.
- Discard and continue discards the affected unsaved changes before navigating.
- Stay preserves the current screen and edits.
- Apply this behavior to breadcrumb navigation, trip or part switching, and browser history navigation.
- Use the browser’s standard unsaved-change warning when closing or reloading the page; custom three-action dialogs are not required for those browser-controlled events.

### Visual design and accessibility

- Redesign all three screens with consistent typography, spacing, buttons, forms, and visual hierarchy.
- Use English for interface labels, navigation, forms, and messages, without changing trip content language.
- Support desktop and tablet layouts, including tablet portrait orientation.
- Keep primary controls usable with touch and keyboard.
- Provide visible focus, labeled controls, and clear loading, empty, error, and success states.
- Mobile editing is outside this redesign.
- Trip and part list entries show titles only; thumbnails, dates, and counts are not required.

### Storage modes

- Apply the new styling and screen organization to both Python-helper and manual-folder modes.
- Helper mode lists repository trips and supports existing trip creation and management capabilities.
- Manual-folder mode begins with Open trip folder rather than automatic repository trip discovery.
- After a folder is selected, manual mode uses the parts and editing screens with its supported capabilities.
- Explain helper-only capabilities clearly rather than presenting unusable actions.

### Constraints

- Preserve static published galleries and existing trip data formats.
- Retain vanilla HTML, CSS, and JavaScript without introducing a build toolchain.
- Keep the local helper on Python 3.10+ standard library, loopback-only, with existing path validation.
- Preserve separate content, registry, and configuration drafts and existing protections against stale asynchronous results and external file changes.
- Preserve existing validation, deletion confirmations, coordinated-write recovery, and Drive-import consent.
- Do not alter existing trip content as part of the interface redesign.

### Out of scope

- Redesigning published trip galleries or other public website pages.
- Mobile editing support.
- Adding an interface language switch.
- Changing media hosting, AI providers, or underlying data schemas.

### Acceptance criteria

- Both launchers open the trip landing screen.
- Existing trips and their parts are selectable through title-only lists.
- New trips open an empty parts screen with Add first part.
- Blank-part creation and reviewed Google Drive import both lead to the created part’s editor.
- Trip settings and part-management actions are available from the parts screen.
- Existing content-editing capabilities remain available on the part screen.
- Breadcrumbs and browser history navigate consistently.
- Unsaved-change navigation offers the three specified choices; failed saves prevent navigation.
- Desktop and tablet layouts support keyboard and touch interaction.
- Manual-folder mode follows the redesigned workflow within its supported capabilities.
- Update .aib_memory/context.md to describe the implemented screens, navigation, draft handling, and mode differences.
