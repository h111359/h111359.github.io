## Input

### Goal

Create a static, browser-based Video & Audio Converter that lets site visitors privately process one MP4 file into MP3, M4A, compressed MP4, or a separately trimmed MP4. All media processing must occur locally in the browser without uploading the source or generated files.

### Users and value

- Primary users are visitors who need simple video compression, audio extraction, or accurate trimming without installing desktop software or uploading private media.
- Site owner benefits by adding a practical third application to the public Projects portfolio.
- Repository currently contains no equivalent media-processing application.
- This feature is the current implementation priority and should be deliverable in one implementation iteration.
- No parties beyond the site owner and application visitors are expected to be affected.

### Deliverables

- Create the application at `apps/video-tool/index.html`.
- Add a third project card to `apps.html` linking to the new application.
- Preserve the existing primary site navigation.
- Host all required application code, styles, FFmpeg WebAssembly assets, workers, and dependency notices within the repository.
- Provide MP3 extraction, M4A extraction, preset-based MP4 compression, and separate accurate MP4 trimming.
- Provide responsive, accessible controls and clear processing feedback.

### Functional requirements

#### Source selection and validation

- Accept one local `.mp4` file at a time through a file picker and drag-and-drop interface.
- Validate the actual media container and decodability instead of trusting only the filename extension or browser MIME type.
- Reject unsupported, corrupt, or undecodable files with a clear user-facing error.
- Display the selected filename, file size, duration, dimensions, and whether an audio track exists.
- Show an in-page video preview after successful validation.
- Replacing the source must clear generated outputs and release obsolete object URLs and processing state.
- Show a soft warning above 500 MB or 30 minutes on desktop devices.
- Show a soft warning above 150 MB or 10 minutes on mobile devices.
- Warnings must explain the browser-memory risk but allow the user to continue.

#### Output selection and processing

- Allow the user to select one or more of MP3 extraction, M4A extraction, and compressed MP4 generation.
- Provide trimmed MP4 as a separate optional transformation.
- Process selected transformations sequentially to reduce peak browser memory usage.
- Display the current job, queued jobs, progress, completion state, and errors.
- Provide a cancel action that stops the active conversion and clears remaining queued work without removing already completed results.
- Provide a reset action that clears the source, outputs, errors, and processing state.
- Keep all media bytes local to the browser and never upload them or send them to an external service.

#### Audio extraction

- Produce MP3 using MP3 audio encoding.
- Produce M4A using AAC audio encoding.
- Offer 128, 192, 256, and 320 kbps audio bitrate presets.
- Default both audio formats to 192 kbps.
- Preserve mono or stereo channel layout where practical and downmix sources with more than two channels to stereo.
- Extract audio from the complete source video regardless of the selected trimming range.
- Disable MP3 and M4A extraction when the source has no audio track and explain why those options are unavailable.

#### Video compression

- Produce an MP4 containing H.264 video and AAC audio.
- Retain the source audio when present and produce a valid silent MP4 when it is absent.
- Preserve aspect ratio and display orientation.
- Never upscale either source dimension.
- Use broadly playable YUV 4:2:0 output and web-optimized MP4 layout.
- Remove nonessential source metadata from the generated file.
- Provide these presets:
  - Small: maximum 480-line resolution, H.264 CRF 32, frame rate capped at 30 fps, and AAC audio at 96 kbps.
  - Balanced: maximum 720-line resolution, H.264 CRF 28, frame rate capped at 30 fps, and AAC audio at 128 kbps.
  - High Quality: maximum 1080-line resolution, H.264 CRF 23, source frame rate preserved up to 60 fps, and AAC audio at 192 kbps.
- Select Balanced by default.
- Display source and result sizes together with the absolute and percentage difference.
- If the compressed result is not smaller than the source, show a warning but retain its download button.
- Do not perform repeated encoding passes to guarantee a target size.

#### Video trimming

- Provide a visual dual-handle timeline for choosing trim start and end positions.
- Make both handles keyboard operable and expose their values through accessible labels and exact time displays.
- Synchronize the selected range with the video preview so the user can inspect it before processing.
- Require the end time to be greater than the start time and keep both values within the source duration.
- Generate trimming as a separate MP4 output; it must not change the MP3, M4A, or compressed MP4 source range.
- Re-encode the trimmed output so its start and end boundaries are within approximately 0.1 seconds of the selected times.
- Encode trimmed video as H.264 at the source resolution and frame rate using high-quality CRF 20 encoding.
- Encode trimmed audio as AAC at 192 kbps when an audio track exists.
- Preserve aspect ratio and display orientation and remove nonessential metadata.
- Produce a valid silent trimmed MP4 when the source contains no audio.

#### Downloads

- Do not trigger automatic downloads.
- Show a separate download button for every successfully generated result.
- Derive safe filenames from the source basename:
  - `<name>_audio.mp3`
  - `<name>_audio.m4a`
  - `<name>_compressed.mp4`
  - `<name>_trimmed.mp4`
- Keep completed outputs available until the source is replaced or the application is reset.
- Release generated object URLs when outputs are discarded or the page is unloaded.

### User experience and accessibility

- Match the cream, charcoal, deep-rust, and muted-sage visual system used by the primary site.
- Reflow without horizontal page scrolling at 320 CSS pixels.
- Support mouse, touch, and keyboard operation.
- Provide visible keyboard focus and practical touch target sizes.
- Give every input and control an accessible name.
- Announce validation, queue, progress, cancellation, completion, and failure states to assistive technology without stealing keyboard focus.
- Do not rely on color alone to communicate state.
- Respect reduced-motion preferences.
- Preserve essential controls and explanatory content if nonessential enhancement code fails.
- Warn users before starting that conversion speed and memory capacity depend on their device.
- Keep the user on the page throughout processing.

### Technical constraints

- The application must remain compatible with GitHub Pages static hosting.
- No server-side code, upload endpoint, build system, package manager, conversion API, analytics upload, or cloud storage may be introduced.
- Use repository-hosted FFmpeg WebAssembly assets; do not load runtime dependencies from a CDN.
- Include required third-party copyright and license notices in the repository and expose an attribution link from the application.
- Use plain HTML, CSS, and vanilla JavaScript consistent with the existing site architecture.
- Target current desktop and mobile versions of Chrome, Edge, Firefox, and Safari.
- Use capability detection and provide a clear compatibility error when required WebAssembly, Worker, Blob, media, or download functionality is unavailable.
- A warning threshold is not a processing guarantee; successful maximum file size remains dependent on available device memory.
- Mobile support requires the same features and responsive controls for files the device can process, but does not guarantee successful conversion of desktop-sized inputs.

### Out of scope

- Multiple-file or batch processing.
- Input formats other than MP4.
- Lossless or stream-copy trimming.
- Cropping, rotating, joining, filtering, overlays, transitions, and color correction.
- Subtitle creation, editing, burning, or extraction.
- Audio-only source files.
- Screen, camera, or microphone recording.
- Cloud storage, account systems, conversion history, or server persistence.
- Automatic downloads or ZIP packaging.
- Exact target-size compression or repeated multi-pass attempts.
- Background processing after the page is closed.
- Offline installation or progressive-web-app behavior.

### Success criteria

- `apps/video-tool/index.html` loads as a static page and is reachable from a third card on `apps.html`.
- Browser network inspection confirms that selected media and generated output bytes are never uploaded.
- FFmpeg and all required runtime assets load from repository paths rather than third-party origins.
- A valid MP4 with audio can independently produce playable MP3 and AAC-in-M4A files at each offered bitrate.
- The same source can produce playable Small, Balanced, and High Quality H.264/AAC MP4 outputs using the documented preset limits.
- Compression results show source size, result size, and percentage difference.
- A compression result that is not smaller remains downloadable and displays a warning.
- A selected trim range produces a separate playable MP4 whose boundaries are within approximately 0.1 seconds of the requested values.
- Trimming does not alter the duration of separately generated audio or compressed-video outputs.
- A silent MP4 can be compressed and trimmed while audio extraction remains disabled.
- Invalid, corrupt, and non-MP4 inputs produce clear errors without starting conversion.
- Selected transformations run sequentially and expose understandable queue and progress states.
- Cancellation stops active and queued work while preserving already completed downloads.
- Every result uses the required filename suffix and downloads only after explicit user action.
- The interface works without horizontal page scrolling at 320 CSS pixels and supports keyboard and touch input.
- The application introduces no server-side or build dependency.

### Verification

- Use a small valid MP4 containing video and audio to test MP3, M4A, all compression presets, trimming, filenames, and download playback.
- Use a small silent MP4 to verify compression, trimming, and disabled audio extraction.
- Use invalid, corrupt, renamed, and non-MP4 files to verify validation and recovery.
- Verify trim-boundary accuracy against the requested start and end values.
- Verify source and result size calculations, including the not-smaller warning path.
- Verify sequential jobs, cancellation, reset, source replacement, repeated conversions, and object-URL cleanup.
- Run automated smoke checks in available Chromium.
- Perform or document a manual compatibility matrix for desktop Chrome, Edge, Firefox, and Safari plus Android Chrome and iOS Safari.
- Test keyboard navigation, visible focus, accessible labels and announcements, touch controls, reduced motion, and the 320 CSS-pixel layout.
- Confirm through network inspection that processing remains local.
- Confirm that dependency licenses and attribution are present.

### Assumptions and risks

- Users understand that in-browser video conversion is slower and more memory-intensive than native desktop software.
- Device memory, browser limits, source codec, duration, resolution, and frame rate can cause a conversion to fail even below a warning threshold; failures must leave the page recoverable.
- Repository-hosted FFmpeg WebAssembly increases the deployed asset size; if asset-size limits prevent deployment, the implementation must stop and report the constraint rather than silently switch to a CDN or external API.
- Browser codec decoding behavior may differ; files that cannot be decoded by the bundled FFmpeg runtime must receive a clear unsupported-media error.
- Current-browser compatibility means the latest stable browser versions available during verification.
