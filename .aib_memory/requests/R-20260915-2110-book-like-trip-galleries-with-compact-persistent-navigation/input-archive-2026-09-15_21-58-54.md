## Input

### Goal
Give trip-gallery visitors a book-like experience showing one image, video, or standalone text item at a time, with compact navigation, wider text areas, and slightly larger text.

### Scope
Apply the changes to all trip galleries using the shared gallery components, including trips/china, trips/2026, trips/2026_portugal, and future trips created from trips/template.

### Header
- Replace the large introductory heading area with a compact header on desktop, tablet, and mobile.
- Display a smaller trip title and the localized “Events” button with a visible text label.
- Target approximately 56–64 CSS pixels in height for a single-line title at default text size.
- Allow the header to grow for wrapped titles and enlarged text.
- Hide the introductory subtitle, eyebrow, facts, and decorative header elements from the header without deleting their configuration values.
- Keep the header visible throughout browsing.
- Allow long titles to wrap without overlapping controls or causing horizontal scrolling.

### Event Navigation
- Hide the Events menu by default on every screen size.
- Open the menu as an overlay without reducing the gallery width.
- Use a side panel on desktop and tablet, expanding to the available screen width on narrow phones.
- Preserve event search, date grouping, current-event indication, and bookmarkable event links.
- Display configured introductory subtitle and trip facts within the panel when available, without allowing them to dominate event navigation.
- Allow the panel’s contents to scroll when necessary.
- Provide keyboard focus containment, Escape dismissal, a close button, and background-click dismissal where the backdrop is visible.
- Make background content inactive while the overlay is open.
- Opening and closing the overlay must not cause horizontal layout movement.
- On opening, focus the close button and ensure the current event is visible in the list.
- Preserve search text while the overlay remains open; clear it when the overlay closes.
- Selecting an event closes the overlay, displays that event’s first available content item, and focuses its event heading.
- Keep the event heading visible below the compact header.
- Dismissing the overlay without selection restores focus to Events and preserves the current item and any internal text-scroll position.
- Keep the menu usable when resizing between desktop and mobile.

### Sequential Event Browsing
- Provide localized “Previous event” and “Next event” controls near the event heading.
- Make applicable event-navigation controls available in the lower navigation area as well.
- Follow the existing event registry order without reordering events.
- Use the same event-loading and bookmarkable-link behavior as selection from the Events menu.
- Switching events displays the destination event’s first available content item and focuses its event heading.
- Omit Previous event at the first event and Next event at the last event.
- Do not wrap between events.
- Omit sequential event navigation for trips containing fewer than two events.
- Clearly distinguish event controls from item controls.
- Keep all controls compact and usable at narrow widths.

### Single-Item Book Layout
- Show exactly one displayed content item at a time in the main gallery.
- Each image, video, or standalone text item represents one book-like page.
- Keep an image or video together with its associated title and caption on the same page.
- Place each standalone text item, including its title and body, on its own page.
- Do not show adjacent items, a vertically stacked item list, or a two-page spread.
- Preserve authored item order and existing visibility rules.
- Hidden media must not create pages or navigation entries.
- Fit the gallery shell within the available viewport without vertical or horizontal document scrolling.
- Keep the compact header, event heading, current content page, and lower navigation available together.
- Calculate the content page’s available space after accounting for headers, controls, margins, and padding.
- Update sizing when the viewport, device orientation, header height, or text size changes.
- Inactive items must not remain visible, keyboard-focusable, or exposed as active content to assistive technology.
- No page-turn animation is required.

### Media and Text Within a Page
- Fit the complete image or video presentation area within the available content space without cropping or distorting it.
- Keep media and its associated text area visible together.
- Use an adaptive arrangement of media and text that suits the viewport proportions.
- Preserve media sources, proportions, titles, captions, authored text, and trusted HTML formatting.
- Keep all text accessible without truncation.
- Allow internal scrolling only within an overflowing caption or standalone text area.
- Do not use document scrolling to reveal the remainder of an item or to move between items.
- Make internal text scrolling usable with keyboard, touch, and pointer input.
- Ensure text areas do not trap focus or prevent access to navigation.
- When navigating to a different item, begin its text area at the top.
- Stop or pause outgoing video playback when changing items so hidden videos do not continue playing.
- Do not automatically play videos or advance pages.

### Text Width and Typography
- Give standalone text and media captions a wide layout using the available width of their content area.
- Remove the approximately 65–75-character reading-width limit.
- Avoid wide empty side columns around text and captions.
- Target combined outer margins and text padding of approximately 12–16 CSS pixels per side on phones and 24–32 CSS pixels per side on tablet and desktop.
- Increase body text and caption font sizes modestly, targeting approximately 10–15 percent above their current sizes.
- Preserve the existing font families, colors, and relative heading hierarchy.
- Maintain comfortable line spacing.
- Do not shrink text to force long content onto one screen.
- Respect browser text enlargement and keep overflowing text accessible through internal scrolling.

### Previous and Next Item Controls
- Provide visibly labeled, localized “Previous item” and “Next item” buttons in the lower navigation.
- Navigate among displayed items in the current event only, following authored order.
- Activating either button replaces the current content page with the destination item.
- Move keyboard focus to the destination item’s heading or an appropriately labeled content focus target.
- Keep the destination content clear of the header and navigation.
- Omit Previous item at the first displayed item and Next item at the last displayed item.
- Do not wrap or automatically move into another event at item boundaries.
- Omit item-navigation controls when there are fewer than two displayed items.
- Keep controls usable with keyboard, touch, and pointer input.
- Respect reduced-motion preferences for any transitions.

### Lower Dot Navigation
- Provide one navigation dot for every displayed content item in the current event.
- Include images, videos, and standalone text items in authored order.
- Use dots rather than image thumbnails.
- Clearly indicate the current item visually and programmatically.
- Activating a dot displays its corresponding item using the same focus behavior as Previous item and Next item.
- Give every dot an accessible label identifying its destination and a practical pointer and touch target.
- Keep the dot navigation in the lower navigation area and account for its height when sizing the content page.
- For events with more dots than fit, use compact pagination of the dots with controls to reach every group; do not require a scrolling strip.
- Keep the current item’s dot in the visible group.
- Omit dot navigation when there are fewer than two displayed items.
- Do not cause horizontal document scrolling.

### Full-Screen Media Viewer
- Keep the magnifier control available for images.
- Activating it opens the current image in a full-screen viewer with zoom capability.
- Preserve existing media-viewer functionality, including video viewing.
- Allow image panning when zoomed.
- Closing the viewer returns to the same item and restores focus to the invoking control.
- Keep the viewer and Events overlay independently dismissible with appropriate focus handling.

### Empty and Single-Event Trips
- Preserve the localized empty-trip state.
- For empty trips, keep the Events panel usable with a clear localized message.
- Omit unnecessary search, event-navigation controls, item-navigation controls, and dots.
- For single-event trips, retain access to the Events panel and trip context but omit event search and sequential event navigation.
- Determine item-navigation availability independently from event count.
- Preserve the existing empty-content state when an event has no displayable items.
- An event with one displayed item shows that item without item-navigation buttons or dots.

### Constraints and Exclusions
- Preserve the static HTML, CSS, and vanilla JavaScript architecture.
- Introduce no production server or build-tool dependencies.
- Preserve trip configuration, localization, event data, authored content, media sources, and visibility rules.
- Preserve trusted authored HTML rendering in text bodies and captions.
- Add localized labels for new controls and states using the existing localization mechanism.
- Keep existing colors and font families.
- Exclude the main portfolio pages, trip editor, and unrelated utilities.
- Preserve existing event-level URL routing and browser Back/Forward behavior.
- New item-level URL routing is not required.
- Normal gallery browsing uses controls to change items; document scrolling and scroll-based item navigation are excluded.
- Internal overflow scrolling for text and the Events panel, and panning within zoomed images, remain permitted.

### Acceptance Criteria
- China, 2026, Portugal, and the trip template use the same shared layout.
- The compact header displays the trip title and visibly labeled Events button without the large introductory section.
- Long titles and enlarged text do not overlap controls or cause horizontal document scrolling.
- The Events menu starts closed and consumes no gallery layout width.
- Opening and closing the menu leaves gallery width and horizontal position unchanged.
- Configured introductory subtitle and trip facts remain accessible in the Events panel.
- Event search, selection, hash navigation, browser Back/Forward navigation, and media viewing remain functional.
- Opening the Events menu shows the full event list with the current event indicated and visible.
- Selecting an event closes the menu, displays its first available item, and focuses its visible event heading.
- Dismissing the menu without selection preserves the current item and internal text position and restores focus to Events.
- Sequential event controls follow registry order, support bookmarkable navigation, and do not wrap.
- Exactly one content item is visible at a time.
- Every displayed image, video, and standalone text item has its own page.
- Media and its associated title and caption remain together on that page.
- The complete media presentation area fits without cropping or distortion.
- Header, current content, and lower navigation remain available without document scrolling.
- Long text and captions remain readable and fully accessible through internal scrolling.
- Text areas have narrow side insets, no previous character-based width limit, and modestly larger body and caption fonts.
- Previous item, Next item, and dots navigate in displayed item order within the current event without wrapping or crossing event boundaries.
- Every item can be reached through dot navigation, including when dots require multiple groups.
- Current-item changes update the active dot and its visible group.
- Hidden media produces neither content pages nor dots.
- Inactive items cannot receive keyboard focus, and outgoing videos do not continue playing.
- The image magnifier opens a full-screen viewer with working zoom and returns to the same item on dismissal.
- Empty trips, single-event trips, and events with zero or one displayed item show only applicable controls.
- At 320 CSS pixels and representative tablet and desktop sizes, the layout has no document scrolling and all content remains accessible.
- Resizing, orientation changes, wrapped titles, and enlarged text preserve usable content sizing and navigation.
- Resizing with an overlay open or closed does not leave inaccessible content, trapped focus, or an incorrectly locked interface.
- Keyboard navigation, internal text scrolling, focus visibility, and reduced-motion behavior remain usable.
