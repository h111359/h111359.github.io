## Input


### Goal

Generalize the existing China family-trip gallery into a reusable static system for publishing multiple trip stories. Preserve the current China gallery URL and content while extracting shared gallery assets, introducing per-trip configuration, relocating the editor to a canonical shared location, and adding a local Python generator that creates event data files from public Google Drive folders.

### Users and value

- Primary user: site owner creating and maintaining family trip stories.
- Public visitors continue viewing trip stories through static GitHub Pages URLs.
- Shared code and tools shall reduce duplication when new trips are created.
- Existing China gallery behavior and public links shall remain functional.

### Deliverables

- Extract reusable gallery application code and styling into `trips/shared/`.
- Keep `china/` as an operational trip folder at its existing public URL.
- Add `china/trip-config.js` and adapt the China gallery to use shared assets.
- Add a reusable starter trip under `trips/template/`.
- Move the canonical data editor to `trips/data_editor.html`.
- Remove `china/data_editor.html`; no compatibility copy or redirect is required.
- Add `scripts/generate_trip_event.py`.
- Add shared-trip documentation under `trips/`.
- Replace the obsolete Google Apps Script instructions in `china/README.md` with references to the shared workflow and Python generator.
- Update `.aib_memory/context.md` to describe the implemented multi-trip architecture and correct obsolete `202507_china/` references to `china/`.

### Multi-trip architecture

- New real trips shall use root-level peer folders such as `china/` and `<trip-slug>/`.
- Each trip folder shall contain its own `index.html`, `trip-config.js`, and `data/` directory.
- Each trip’s `data/events.js` shall define `window.GALLERY_EVENT_INDEX`.
- Each event data file shall define `window.GALLERY_ITEMS`.
- Shared gallery application code and styling shall reside under `trips/shared/`.
- Trip folders shall reference the shared assets rather than copying them.
- `trips/template/` shall provide a copy-ready starting structure but shall not represent or publish another real trip.
- The primary four-page career-site navigation shall remain unchanged.
- No trip landing page or new primary navigation item is required in this iteration.

### Trip configuration

Each trip shall provide a JavaScript configuration object consumed by the shared gallery application. It shall support at least:

- Document language and locale.
- Page title.
- Hero eyebrow.
- Main trip heading.
- Subtitle.
- Trip facts or date summary.
- Page description.
- Theme values that genuinely need to vary by trip.

The China configuration shall preserve its current Bulgarian presentation and metadata. The shared application shall use the configured language and locale for displayed dates and trip-level interface content.

### Shared editor

- `trips/data_editor.html` shall become the only canonical editor.
- The editor shall remain a standalone static HTML tool using the File System Access API.
- It shall open and edit the selected `data/` directory of any trip.
- It shall continue supporting `events.js`, media and text items, descriptions, visibility, ordering, validation, polling, dirty-state protection, and in-place saves.
- China-specific wording and path assumptions shall be removed from the shared editor.
- Existing event data schemas and rich-text behavior shall remain compatible.
- The editor shall not need to query Google Drive or generate files from Drive folders.

### Google Drive event generator

Create a Python 3.10+ command-line script at `scripts/generate_trip_event.py`.

The script shall:

- Accept a publicly shared Google Drive folder URL or folder ID.
- Accept a caller-specified local output `.js` path.
- Use credential-free inspection of the public Google Drive folder.
- Require no OAuth login, API key, credential file, or secret.
- Inspect direct children only.
- Include image and video files.
- Skip nested folders, shortcuts, Google-native documents, and unsupported file types.
- Sort included media by natural filename order.
- Handle all discovered direct children without an arbitrary single-page limit.
- Generate one event data file per invocation.
- Write output in the existing `window.GALLERY_ITEMS = [...]` format.
- Populate each generated media record with its Drive filename, preview URL, empty `desc`, and `visible: true`.
- Preserve a Drive resource key in the generated preview URL when one is exposed and required.
- Escape filenames and URLs safely for JavaScript string literals.
- Report skipped and inaccessible items clearly.
- Fail without creating a partial output when the folder cannot be inspected, contains no supported media, or any selected media cannot be verified as publicly accessible.
- Never change Google Drive permissions.
- Never modify `events.js`.
- Leave event registration to the shared data editor.

A normal generated record shall be equivalent to:

```js
{ name: "photo.jpg", preview: "https://drive.google.com/file/d/FILE_ID/preview?authuser=0", desc: "", visible: true }
```

### Existing-output behavior

- When the output path does not exist, create the complete event file.
- When it already exists, warn that replacement removes descriptions, text blocks, visibility settings, and custom ordering.
- Replace it only after explicit user confirmation or an explicit overwrite command-line option.
- If replacement is declined, leave the existing file byte-for-byte unchanged.
- Replacement shall regenerate the entire file from the current Drive folder contents; no merge behavior is required.

### Public-access validation

- The generator shall make unauthenticated requests when discovering and validating media.
- It shall verify public accessibility as far as the credential-free mechanism permits.
- It shall not assume that a public folder automatically makes every child file accessible.
- Validation failures shall identify the affected file when its name or ID is available.
- No Google credentials, tokens, folder URLs, or generated family-media identifiers shall be committed as configuration fixtures.

### Credential-free extraction risk

Google does not provide an officially supported unauthenticated `files.list` workflow. Credential-free enumeration may therefore depend on undocumented data exposed by the public Google Drive interface.

The implementation shall:

- Isolate Drive-page parsing from JS serialization and filesystem writing.
- Detect unexpected or incomplete response structures.
- Exit with a non-zero status and an actionable message when Google’s public response can no longer be interpreted.
- Avoid silently producing incomplete galleries.
- Document this limitation and the recovery option of updating the isolated parser if Google changes its public interface.

### China compatibility

- Preserve the public `china/` gallery URL.
- Preserve existing event hashes and registered event slugs.
- Preserve all existing `china/data/*.js` story content.
- Preserve image, video, text-block, rich-text, visibility, navigation, search, and lightbox behavior.
- Do not resolve unrelated existing content or registry quality issues as part of this request.
- Do not modify the user’s current edits in `china/data/event-20250721-nefrit-buda.js`.

### Starter template

The starter trip shall include:

- A minimal `index.html` wired to shared assets.
- A documented `trip-config.js` with placeholder values.
- A `data/events.js` containing a valid empty or example-free registry.
- A valid empty event-data template if required by the documented workflow.
- Instructions for copying the template, editing configuration, generating event files, registering events through the shared editor, and publishing through GitHub Pages.

### Out of scope

- Publishing a second real trip.
- Adding a trip selector that combines all trips into one application.
- Adding a Trips item to the primary site navigation.
- OAuth, Google API keys, or Google Cloud project setup.
- Automatic Google Drive permission changes.
- Recursive Drive folder import.
- Automatic modification of a trip’s `events.js` by the Python generator.
- Merging regenerated media with manually edited event content.
- Introducing server-side code, a build toolchain, or a JavaScript package manager.
- Fixing unrelated China gallery content, registry, comments utility, or legacy-site issues.

### Verification and acceptance criteria

- Loading the existing `china/` URL displays the China trip with its current title, events, media, navigation, search, and lightbox behavior.
- Existing China event hashes continue opening the corresponding event.
- China loads its trip-level content from `china/trip-config.js` and its application assets from the shared location.
- No existing China event data content is lost or rewritten.
- Copying `trips/template/` to a new root-level trip folder and editing its configuration produces an independently addressable static trip.
- `trips/data_editor.html` can open China’s `data/` directory, load `events.js`, edit an event, and save it in the existing schema.
- `china/data_editor.html` no longer exists.
- `python scripts/generate_trip_event.py --help` documents the folder input, output path, overwrite behavior, limitations, and examples.
- Given a compatible public Drive folder, the generator emits one syntactically valid `window.GALLERY_ITEMS` file containing every supported direct-child image and video exactly once in natural filename order.
- Unsupported files, folders, and shortcuts are omitted and reported.
- Generated records use empty descriptions and `visible: true`.
- The generator does not change Drive permissions or modify any `events.js`.
- Existing output is not replaced without explicit confirmation or an explicit overwrite option.
- Discovery, validation, or parsing failure leaves no new partial file and preserves an existing output.
- Automated tests cover folder-ID extraction, natural sorting, media filtering, JavaScript escaping, serialization, overwrite refusal, and representative Drive-response parsing fixtures.
- Browser verification covers both the refactored China gallery and the starter trip.
- `.aib_memory/context.md` records the shared multi-trip architecture, shared editor, generator behavior, credential-free risk, and correct `china/` path.
