## Input


### Goal

Fix portrait-image previews in `trips/data_editor.html` so the complete image is always visible within the existing square preview frame without cropping or clipping.

### User and Need

The site owner uses the trip data editor to review and correct gallery media. Portrait images currently lose visible portions inside their editor preview, preventing reliable review of the complete photograph.

### Reproduction Case

- Trip data: `china/data/event-20250725_15-white-emperor.js`
- Media filename: `20250725_155603.jpg`
- Source orientation: portrait
- Saved rotation: none
- Affected surface: preview card in `trips/data_editor.html`

### Scope

- Correct portrait-image containment in preview cards rendered by `trips/data_editor.html`.
- Retain the existing square preview frame with a maximum size of 400 CSS pixels.
- Scale each recognized image proportionally so all source pixels remain visible.
- Support portrait, landscape, and square source images without cropping.
- Keep the complete image visible at rotations of 0°, 90°, 180°, and 270°.
- Keep the complete image visible with horizontal flip, vertical flip, or both applied.
- Ensure the behavior remains responsive at desktop and mobile-sized viewport widths supported by the editor’s Chromium environment.
- Preserve the editor’s existing media fields, controls, save behavior, and unrelated in-progress video-entry presentation changes.

### Out of Scope

- Changes to the public trip gallery.
- Changes to trip data records or Google Drive source files.
- Changes to video-thumbnail or generic-media containment behavior.
- Replacement or modification of source images.
- Introduction of frameworks, build tools, server-side code, or external dependencies.

### Constraints

- The editor must remain a standalone static HTML file using vanilla HTML, CSS, and JavaScript.
- The preview frame must remain square and no larger than 400 CSS pixels.
- Images must preserve their natural aspect ratio.
- Empty space within the square frame is acceptable when required to display the complete image.
- Existing landscape and square images must remain fully visible without cropping.
- Existing rotation and flip controls must continue to work and accurately represent the resulting image.
- Existing uncommitted changes in `trips/data_editor.html` must be preserved.

### Assumptions

- The Google Drive thumbnail for `20250725_155603.jpg` contains the complete source image.
- The defect is caused by editor preview layout or transformation behavior rather than cropping performed by the source service.
- “Mobile-sized viewports” means responsive viewport widths tested in a supported Chromium-based environment; it does not expand File System Access API browser support.
- If a source thumbnail is already cropped by Google Drive, that limitation must be reported rather than hidden by unrelated changes.

### Acceptance Criteria

- The preview of `20250725_155603.jpg` displays the complete photograph with no clipped top, bottom, left, or right edge.
- Every recognized portrait image with a valid thumbnail URL fits proportionally inside the existing square preview frame.
- The preview frame remains square, centered, responsive, and capped at 400 CSS pixels.
- Portrait, landscape, and square images remain completely visible at 0°, 90°, 180°, and 270°.
- Images remain completely visible when horizontal flip, vertical flip, or both are active at every supported rotation.
- No tested image is stretched or distorted.
- At viewport widths down to 320 CSS pixels, the preview fits within the page without horizontal page overflow.
- Video and generic-media presentation remains unchanged.
- The public gallery and trip data files remain unchanged.
- Existing editor loading, editing, rotation, flipping, visibility, and saving workflows continue to function.
