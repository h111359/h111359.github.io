## Input

### Goal

Да се създаде лесен локален browser workflow за създаване и редактиране на trip страници, без запомняне на аргументите на `scripts/generate_trip_event.py` и без ръчно конфигуриране на локален preview server.

### User and value

- Основен потребител: собственикът на сайта.
- Текущ проблем: създаването на trip/event изисква ръчни команди, редактиране на няколко JavaScript файла и отделно стартиране на локален server.
- Очаквана полза: по-малко ръчни стъпки, по-малък риск от несъответствие между `events.js` и `event-*.js`, и лесен локален preview.
- Други засегнати страни няма; посетителите виждат само публикувания статичен резултат.

### Terminology

- Trip е цял пътепис като `trips/china/`, достъпен през един `index.html`.
- Part е отделна навигируема страница в trip-а, представена от един `data/event-*.js` файл и един запис в `data/events.js`.
- Един trip може да бъде празен, да съдържа само една part или да съдържа множество parts.

### Selected approach

Да се разшири съществуващият `trips/data_editor.html` като единен browser interface за:

- създаване на нов trip;
- избор и редактиране на съществуващ trip;
- редактиране на `trip-config.js`;
- управление на parts чрез `data/events.js`;
- генериране на `event-*.js` от публични Google Drive папки;
- локален preview на trip-а и избраната part.

Editor-ът да се стартира с двойно щракване чрез Linux `.desktop` и Windows `.bat` launcher. Launcher-ите да стартират ограничен локален Python процес, да обслужват repository root през HTTP и да отварят editor-а в браузър.

### New trip workflow

- Показване на действие „Create new trip“.
- Задължително поле за име на trip-а.
- Автоматично генериране на редактиируем URL-safe slug.
- Създаване само под `trips/<trip-slug>/`.
- Копиране на структурата и файловете от `trips/template/`.
- Блокиране на операцията, ако директорията вече съществува, с възможност съществуващият trip да бъде отворен в editor-а.
- Google Drive URL да бъде незадължителен, така че да може да се създаде празен trip.
- Българският език и locale да бъдат defaults; английският да бъде наличен като избор.
- Кратката форма да съдържа основните полета, а останалите настройки на `trip-config.js` да бъдат в разгъваем advanced panel.
- След създаване новият trip автоматично да бъде избран в editor-а.

### Trip settings

Да се добави панел „Trip settings“, който зарежда и записва поддържаните стойности от избрания `trip-config.js`, включително:

- language и locale;
- page title;
- hero eyebrow;
- heading;
- subtitle;
- trip facts;
- page description;
- поддържаните theme стойности;
- локализираните labels.

Записването да запазва валиден `window.GALLERY_TRIP_CONFIG` формат и да не премахва поддържани стойности без предупреждение.

### Trip selection

- При стартиране през launcher editor-ът автоматично да открива валидните директории под `trips/<slug>/`.
- Template и shared директориите да не се показват като реални trips.
- Да има dropdown за избор на trip.
- Да се запази резервната възможност за ръчно избиране на `data/` папка чрез текущия File System Access workflow.
- Съществуващите event editing, rich-text, media visibility, rotation, ordering и AI функции да останат работещи.

### Part and events.js workflow

- Съществуващият registry editor за `events.js` да бъде използван и подобрен.
- Потребителят да може да добавя, редактира, подрежда и изтрива parts.
- За нова part да се въвеждат дата, заглавие и публичен Google Drive folder URL.
- Slug-ът и името `event-*.js` да се генерират автоматично от датата и заглавието, но да могат да бъдат редактирани преди запис.
- Google Drive URL да се използва за генерирането, без да се добавя към публичната схема на `events.js`.
- Един Drive URL да генерира една part от директните медийни файлове в папката.
- Добавянето на следващи parts да става през същия registry editor.
- Trip с една part да бъде напълно поддържан без изискване за допълнителни registry записи.

### Drive generation

- Да се използва съществуващата логика от `scripts/generate_trip_event.py`, без дублиране на parser и validation поведението, но за целта да се генерират нови скриптове в `trips/scripts/` папка.
- Да се запазят текущите ограничения: публична папка, без credentials, само директни файлове, без обхождане на подпапки.
- Преди запис да се покажат резултатът от откриването, броят валидни медии и пропуснатите елементи.
- След потвърждение `event-*.js` и съответният запис в `events.js` да се запишат като една координирана операция.
- При неуспешно генериране `events.js` да остане непроменен.
- При неуспешен registry запис да не остава недостъпен частично създаден event.
- Повторно генериране на съществуващ файл да бъде блокирано по подразбиране.
- Замяна да се допуска само след явно предупреждение, че описания, text blocks, visibility, corrections и custom ordering ще бъдат загубени.

### Preview

- Launcher-ът да стартира local HTTP server, ограничен до loopback интерфейса.
- Editor-ът да има бутон „Preview trip“.
- При избрана part preview бутонът да отваря URL с правилния `#event=<slug>` hash в нов browser tab.
- Preview да работи без ръчно въвеждане на server команда или URL.
- Спирането на launcher процеса да прекратява local server-а чисто.

### Template alignment

- `trips/template/index.html` да използва `../shared/gallery.css` и `../shared/gallery.js`, съответстващи на структурата `trips/<slug>/` и на `trips/china/index.html`.
- Съществуващите `trips/china/index.html` и `trips/2026/index.html` да не се променят в рамките на тази заявка.
- Новите trips да се създават единствено от актуализирания template.

### Constraints

- Публикуваните trips трябва да останат чисти статични HTML, CSS и JavaScript файлове за GitHub Pages.
- Local helper може да използва Python 3.10+, но без външни Python packages, package manager или build system.
- Local helper трябва да слуша само на loopback адрес и да ограничава file operations до repository-то и `trips/`.
- Съществуващата схема `window.GALLERY_EVENT_INDEX` с `slug`, `title` и `data` трябва да се запази.
- Съществуващата схема `window.GALLERY_ITEMS` и поведението на shared gallery трябва да се запазят.
- Съществуващият CLI generator и тестовете му трябва да продължат да работят.
- Работата трябва да е съвместима с Linux и Windows launchers.

### Out of scope

- Git commit, push или автоматично публикуване в GitHub Pages.
- Google Drive authentication, OAuth или промяна на Drive permissions.
- Рекурсивно обработване на Drive подпапки.
- Промяна на съдържанието на съществуващите China и 2026 trips.
- Production server или server-side dependency за публикувания сайт.
- Промяна на shared gallery дизайна, освен ако е необходима минимална корекция за коректно показване на trip с една part.

### Assumptions

- Python 3.10+ е наличен на Linux и Windows машините. Ако не е, launcher-ът няма да може да стартира local helper-а.
- Drive папките са публично достъпни. Ако не са, съществуващият generator трябва да върне ясно съобщение за грешка.
- Един Drive folder съответства на една navigable part.
- Drive URL не е необходимо да се съхранява в `events.js`; ако по-късно е нужно повторно генериране, URL се въвежда отново.
- Chromium остава необходим за резервния File System Access режим; основният launcher workflow може да използва local helper API.

### Acceptance criteria

- Двойно щракване върху Linux или Windows launcher стартира editor-а и local server без ръчно въвеждане на аргументи.
- Editor-ът показва валидните trips под `trips/` и позволява резервен ръчен избор на `data/` папка.
- Нов празен trip може да бъде създаден от template-а само с име.
- Опит за създаване върху съществуващ slug не променя нито един файл.
- `trip-config.js` може да бъде създаден и впоследствие редактиран чрез „Trip settings“.
- Една публична Drive папка може да създаде една part, нейния `event-*.js` файл и синхронизиран запис в `events.js`.
- Към съществуващ trip могат да се добавят множество parts.
- Trip с точно една part се зарежда и preview-ва коректно.
- Неуспешна Drive validation не променя `events.js`.
- Замяна на съществуващ event файл изисква явно предупреждение и потвърждение.
- „Preview“ отваря правилния local HTTP URL и избраната `#event=<slug>` страница.
- Всички текущи editor функции и CLI generator тестове остават работещи.
- Добавят се автоматизирани тестове за path validation, trip creation, collision protection, config serialization, registry synchronization и failure rollback.
- `trips/README.md` се актуализира към каноничната структура `trips/<slug>/`, новите launchers и editor workflow.
- `.aib_memory/context.md` се актуализира с текущата `trips/` архитектура и новия локален workflow.
