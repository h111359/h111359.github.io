## Input

### Goal

Make video entries in `trips/data_editor.html` immediately and accessibly distinguishable from image entries while editing trip event data.

The primary user is the site owner editing gallery records. The current editor presents images and videos with the same `📷 Media` label and appearance, making videos difficult to identify when scanning an event.

### Priority and value

Implement in the current iteration to reduce media-identification mistakes during trip-data editing. Public gallery visitors and public rendering behavior are not affected.

### Scope

- Modify only `trips/data_editor.html`.
- Classify media from the case-insensitive filename extension in the editable `name` field.
- Classify `.mp4`, `.m4v`, `.mov`, and `.webm` as video, matching the public gallery’s existing detection rule.
- Classify the repository’s supported image extensions `.avif`, `.bmp`, `.gif`, `.heic`, `.heif`, `.jpeg`, `.jpg`, `.png`, `.tif`, `.tiff`, and `.webp` as image.
- Classify blank filenames and filenames with any other extension as generic media.
- Display confirmed images with a `📷 Image` card-header label.
- Display confirmed videos with a `▶ Video` card-header label, a persistent play indicator over the existing Google Drive thumbnail, and a distinct video accent color.
- Display unrecognized or blank filenames with the neutral `Media` label and without video-specific styling.
- Use text and icon differences in addition to color so media type remains distinguishable without color perception.
- Update the card label, type-specific classes, play indicator, and correction-control visibility immediately as the user types in the Name field.
- Preserve the current Google Drive thumbnail for both images and videos; do not embed or play video in the editor.
- Hide flip and rotation controls for confirmed video cards.
- Preserve existing correction-control behavior for non-video media.
- Rename all `Add photo entry` controls to `Add media entry`.
- Rename all between-item `＋ Photo` controls to `＋ Media`.
- Preserve the existing media-record creation behavior behind the renamed controls.
- Preserve dirty-state tracking, reordering, deletion, visibility editing, rich-text editing, refresh behavior, and saving.

### Constraints

- Keep the editor as a standalone static HTML file using vanilla HTML, CSS, and JavaScript.
- Preserve compatibility with Chrome 86+ and Edge 86+ and the File System Access API workflow.
- Do not add dependencies, server-side functionality, or build tooling.
- Do not add a media-type property or otherwise change the event-data schema.
- Do not infer media type from the Google Drive preview URL.
- Preserve current serialization and existing event-file contents unless the user edits them.
- Avoid relying on color alone; visible labels and icons must communicate the media type.
- Treat the play indicator as a type cue, not as an interactive player control.
- Existing unsaved field values must not be lost when the displayed type changes.

### Out of scope

- Changes to `trips/shared/gallery.js`, `trips/shared/gallery.css`, trip event data files, or the public gallery.
- Embedded video playback inside the data editor.
- Separate Add Image and Add Video controls.
- Changes to Google Drive URLs or thumbnail generation.
- New media schema fields or migration of existing records.

### Acceptance criteria

- A filename ending in `.mp4`, `.m4v`, `.mov`, or `.webm`, regardless of extension case, produces a visibly accented `▶ Video` card with a persistent play indicator.
- Confirmed video cards do not display flip or rotation controls.
- A filename ending in a supported image extension produces a `📷 Image` card without the video accent or play indicator.
- A blank or unrecognized filename produces a neutral `Media` card without video-specific styling.
- Changing the Name field between image, video, and unrecognized extensions updates the same card immediately without reloading the event.
- Immediate type updates preserve all current field values and mark the editor dirty through the existing change workflow.
- Video and image cards remain distinguishable when color is unavailable because their text labels and icons differ.
- Google Drive thumbnails continue to load through the existing thumbnail URL logic.
- All top, bottom, and between-item creation buttons use media-neutral wording while retaining their current insertion behavior.
- Saving produces the existing event-data schema with no generated media-type property.
- Existing editor operations continue to work without browser console errors.
- The editor remains usable at its existing supported viewport sizes and in Chrome 86+ or Edge 86+.
